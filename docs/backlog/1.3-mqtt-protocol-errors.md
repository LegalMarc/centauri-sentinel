# Missing MQTT Protocol Errors Swallowed by Reconnection Loop Logic

**ID:** 1.3
**Severity:** Medium
**Category:** Stability
**Status:** Closed

## Affected Files
- `sentinel/printer/client.py`

## Description
MQTT protocol and parsing errors are swallowed by the reconnection loop logic. Instead of alerting or failing fast on parsing errors, the listener loops silently reconnecting, masking underlying issues.

## Evidence
- Exception handlers in reconnection loop catch all exceptions (including parse/format errors) and trigger reconnect without logging detailed traceback.

## Impact
- Difficulty debugging compatibility issues with printer firmware updates or payload format changes, leading to silent failures.

## Acceptance Criteria
- [x] Identify and propagate permanent/protocol errors while retrying only transient connection errors
- [x] Log distinct warnings for message protocol mismatches
- [x] Test reconnection behavior on malformed payloads vs connection loss
- [x] Tests pass
- [x] Coverage maintained ≥ 85%
