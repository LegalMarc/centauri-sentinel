# TCP Connection Churn for Continuous MJPEG Frame Grabs

**ID:** 1.4
**Severity:** Medium
**Category:** Performance
**Status:** Closed

## Affected Files
- `sentinel/camera/mjpeg.py`

## Description
Continuous MJPEG frame grabbing opens and closes a new HTTP/TCP connection every 10 seconds. This results in heavy connection churn and high socket overhead.

## Evidence
- mjpeg.py makes a new HTTP request for every frame grab instead of keeping the connection open or reusing a connection pool.

## Impact
- Unnecessary TCP handshake overhead, file descriptor exhaustion, and high CPU usage on low-power devices.

## Acceptance Criteria
- [x] Reuse TCP connections or use a persistent client session for frame grabbing
- [x] Verify socket reuse and reduced socket setup/teardown overhead
- [x] Add performance tests verifying persistent connection usage
